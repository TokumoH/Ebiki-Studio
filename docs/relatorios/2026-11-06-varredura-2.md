# Varredura 2 e simulações do sistema — 2026-11-06

Executada após a Fase 3, a publicação do repositório, a revisão dos PRs do Dependabot e a
preparação da release v0.1.0. Checklist: [`docs/processo/varredura.md`](../processo/varredura.md).

## 1. Simulação de sistema (nova)

`crates/infra-adapters/tests/simulation.rs` monta uma sessão realista **pelas mesmas portas que a
interface usa**, com as implementações reais (codecs, DSP, SQLite, engine):

- 32 faixas (mínimo do RNF-05) com as cadeias de efeitos dos presets de instrumento;
- 2 buses (reverb e delay) com envios de todas as faixas; master com a cadeia de masterização
  (limiter com look-ahead → compensação de latência);
- edições não destrutivas em ¼ das faixas (divisão, fades, reverso, polaridade) e mudança de
  andamento 120 → 96 BPM;
- render bloco a bloco medindo cada bloco contra o prazo de tempo real, dentro de
  `assert_no_alloc` (o caminho de tempo real não pode alocar).

### Resultados (release, 1 núcleo do container de desenvolvimento)

| Sessão | Buffer (prazo) | CPU média do prazo | p99 | Blocos acima do prazo | Alocações |
|---|---|---|---|---|---|
| **32 faixas** | **128 (2,67 ms)** | **12%** | 0,37 ms | **0 / 3000** | **0** |
| 32 faixas | 64 (1,33 ms) | 12% | 0,23 ms | 4 / 6000 | 0 |
| 64 faixas | 128 | 28% | 1,22 ms | 3 / 3000 | 0 |
| 128 faixas | 128 | 54% | 2,27 ms | 3 / 3000 | 0 |

- **Capacidade estimada: ~110 faixas com cadeias completas** dentro do orçamento de 50% de CPU
  (3,5× o mínimo do RNF-05). Os raros blocos acima do prazo vêm do escalonamento do container
  (a thread do teste não tem prioridade de tempo real; no app ela tem).
- Pico de saída 0,891 = −1 dBFS: o limiter do master segura o pico em qualquer tamanho de sessão.
- Exportação da mesma sessão duas vezes → amostras idênticas; salvar, fechar e reabrir → exportação
  **idêntica bit a bit** (persistência sem perda de nenhum parâmetro de mixagem ou edição).
- Os limites (média ≤ 50% e p99 ≤ 100% do prazo) são verificados na CI em release, a cada push.

## 3. Erros encontrados e corrigidos

| Erro | Causa | Correção |
|---|---|---|
| **Release v0.1.0 falhou nos 3 sistemas** | `tauri-action` v1 (PR do Dependabot) executa o `beforeBuildCommand` fora da raiz e procurava `crates/ui/package.json` | A action roda da raiz com `tauriScript: npm run tauri` — mesmo fluxo validado localmente |
| Tags não podem ser enviadas deste ambiente | proxy do git aceita apenas a branch de trabalho | Workflow de release com início manual cria a tag no GitHub e valida a versão contra o `tauri.conf.json` |
| Duplicação acima do registrado | Fase 3 e testes novos | Extrações descritas no item 2 |

## 4. Recomendações (próximos ciclos)

1. **Engine multinúcleo**: renderizar faixas independentes em paralelo (pool fixo, sem alocação)
   elevaria a capacidade além de ~110 faixas e reduziria o p99.
2. **Compensação de latência nos buses** (hoje só nas faixas).
3. **Assinatura dos instaladores** (Windows Authenticode, Apple notarização) para remover os avisos
   de app não assinado.
4. **Pacote de bases CC0** no manifesto.

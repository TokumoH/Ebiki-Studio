Ebiki Studio · documento de arquitetura · 2026-11-05

Estúdio musical desktop em Rust, Tauri e React

Gravação, mixagem, edição, harmonia, notação e afinação num só app para Windows, macOS e Linux. Organizado em DDD com contextos independentes, serviços técnicos isolados (Pure Fabrication) e componentes reutilizáveis.

01Contexto do sistema

O app conversa com duas coisas fora dele: a interface de áudio, pelas APIs nativas de baixa latência de cada sistema, e o disco, onde cada projeto é uma pasta portátil.

flowchart LR
    user([Músico / Usuário])
    app[Ebiki Studio<br/>Estúdio desktop]
    dev[(Interface / placa de áudio<br/>ASIO · WASAPI · CoreAudio · JACK)]
    fs[(Sistema de arquivos<br/>projetos .ebiki, áudios, soundfonts)]
    user -- grava, mixa, edita, compõe --> app
    app -- entrada / saída de áudio --> dev
    app -- lê / grava projetos e arquivos --> fs

02Camadas

Arquitetura hexagonal. O domínio é puro, sem I/O, e declara portas (traits). A infraestrutura implementa essas portas.

flowchart TB
    subgraph UI["UI — React + TypeScript"]
        comps[Componentes por contexto<br/>Design System · Painéis]
    end
    subgraph IF["Interface — Rust"]
        cmds[Comandos Tauri · DTOs · Mapeadores]
    end
    subgraph APP["Application"]
        uc[Casos de uso · CommandBus · History]
    end
    subgraph DOM["Domain — puro, sem I/O"]
        dom[Entidades · VOs · Agregados<br/>Eventos · PORTAS traits]
    end
    subgraph INF["Infrastructure — Pure Fabrication"]
        inf[AudioEngine · CodecService · SqliteRepository<br/>FileStorage · SoundfontSynth · DspLibrary]
    end
    UI -- IPC commands --> IF
    IF -- events / channels --> UI
    IF --> APP --> DOM
    INF -. implementa portas .-> DOM
    APP --> INF

Regra de dependência: tudo aponta para o domínio. O domínio não conhece nenhuma outra camada.

04Engine de áudio

A thread de áudio nunca espera: sem alocação, sem lock, sem disco, sem log. Tudo chega a ela por filas lock-free.

flowchart LR
    UI[UI WebView] -- IPC commands --> CT[Control Thread<br/>Application + Domain]
    CT -- events ~30 Hz / channels --> UI
    CT -- SPSC lock-free:<br/>RenderGraph, parâmetros --> AT[AUDIO THREAD<br/>callback tempo real]
    AT -- ring buffer:<br/>medidores, posição, xruns --> CT
    DR[Disk Reader Threads] -- ring buffers --> AT
    AT -- ring buffers --> DW[Disk Writer Thread<br/>WAV float32]
    AN[Analysis Thread<br/>picos, espectrograma, LUFS] -.-> CT

05Persistência

Dois bancos SQLite: project.db dentro da pasta de cada projeto e library.db com o conhecimento musical e as preferências. Mínimo 3FN/FNBC, 4FN nas relações multivaloradas. Progressões ficam em graus relativos, então "I–V–vi–IV" é uma linha só.

06UI, IPC e desfazer

Toda alteração passa pelo CommandBus e entra no histórico. Ações que não mudam o projeto, como play e zoom, ficam de fora.

sequenceDiagram
    participant UI
    participant IPC as Comando Tauri
    participant Bus as CommandBus
    participant Cmd as MoveClipCommand
    participant Dom as Domínio (Project)
    participant Eng as AudioEngine
    participant Hist as History

    UI->>IPC: move_clip(clipId, novoTick)
    IPC->>Bus: dispatch(MoveClipCommand)
    Bus->>Cmd: execute()
    Cmd->>Dom: clip.move_to(novoTick)
    Dom-->>Bus: [ClipMoved]
    Bus->>Hist: push(cmd)
    Bus->>Eng: recompila RenderGraph
    Bus-->>UI: event ClipMoved
    Note over UI,Hist: Ctrl+Z
    UI->>IPC: undo()
    IPC->>Hist: pop()
    Hist->>Cmd: undo()
    Cmd->>Dom: clip.move_to(tickAnterior)
    Bus-->>UI: event ClipMoved
